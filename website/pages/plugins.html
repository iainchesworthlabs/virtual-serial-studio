Plugins and integrations

A plugin connects Studio to something else: a test framework that drives it, a computer that watches it, or a simulated device that answers through it. The official plugins are the Pro edition.

In development

The plugins on this page are being built and none can be downloaded yet. The page describes what the first version will contain. Details may change.

Language and framework bindings

Each binding does the same things: create ports, link them, send and expect bytes, inject faults and read the event log. All of them are in the first version.

Response timing and fault injection

A test harness can set and change these during a run.

Response timing

A delay or jitter on a reply, fixed or drawn from a distribution. Slow a simulated device to the speed of the real instrument, or past your program's timeout.

Scripted replies

When this pattern arrives, answer with that, after this long, a given number of times or in a set order.

Fault injection

Drop, corrupt, truncate or duplicate a reply. Raise a line error, or drop a control line at the moment you choose.

Repeatable runs

A deterministic mode with a seeded random source, so a repeated run makes the same decisions. Real times still depend on the machine.

One clock

A timestamp on everything the harness sees, from a single clock, so events on different ports can be put in order.

Timing in the engine

The engine carries out the delays, replies and faults that a test sets as rules, and the RS-485 turnaround delay, without waiting for a plugin. An action is never early, and the engine records how late each one was.

Remote control and remote monitoring

Run Studio from a CI machine or a rig controller, and watch a running Studio from one other computer. The control endpoint is off until you turn it on. There are three levels of access, and each needs more setup than the one before.

  1. Local only, the default. A local socket that only programs on the same computer and account can reach.
  2. Token. You make a token on the receiving side and give it to the sending side. A token can be revoked and can be limited to certain actions.
  3. Administrator control. OAuth 2.0 and OpenID Connect with an external identity provider, and the client credentials grant for unattended rigs, for sites that manage access centrally.

Plugin isolation and trust

A plugin runs in a process of its own. If it crashes it cannot take Studio down, its permissions can be limited, and its code never runs inside the window.

Your decision to trust a plugin is tied to the exact file. If the file changes, Studio asks you again.

An administrator can set a policy that allows only official plugins.
Write your own
The plugin API is documented and free to use in every edition. The official plugins that we build on it are commercial. A plugin declares what it extends, its settings and its permissions in a manifest, and its author chooses its licence. We do not support third-party plugins.
What a plugin can extend
Generators that put bytes or traffic patterns onto a port, fixture types that answer like a real instrument or modem, behaviour modifiers that delay, corrupt, filter or rewrite traffic on a link, and adapters that let other tools drive Studio.
