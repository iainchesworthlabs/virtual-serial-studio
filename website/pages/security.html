Security policy

Report a vulnerability in private

Please do not report a security problem as a public issue or pull request. Use GitHub's private vulnerability reporting, which opens an advisory that only you and the maintainer can see.

Report a vulnerability on GitHub

If you cannot use that form, open an ordinary issue that says only that you have a security matter, with no details, and the maintainer will reply there to arrange a private channel.

The policy that binds us is the file SECURITY.md in the repository. This page is a summary of it.

What helps most

  • What is affected: the version, from the About dialog or vss_gui --version, the operating system, and whether it is the application, vss_cli or a release file.
  • How to reproduce it: the smallest setup file, command line or byte stream that shows it.
  • What someone could do with it.

Please do not attach traffic captured from equipment that is not yours.

What counts

Studio opens serial ports, creates virtual ones, and can bridge a port to TCP, RFC 2217 or UDP. So these count:

  • a crash, a hang, an out-of-bounds read or another memory-safety fault that crafted bytes can cause, from a network endpoint or from a setup file;
  • a network endpoint that accepts a peer the user did not ask it to, or that exposes a port the user did not share;
  • anything that lets one program read or write another program's virtual port without being given it;
  • a flaw in the Windows COM port driver, in the build and workflow files, or in what the release process publishes;
  • a flaw in this website.

The bridges do not authenticate or encrypt. Plain TCP, RFC 2217 and UDP have neither, and a hostile network is outside what they defend against. A report that depends only on that describes a limit of the protocol.

What to expect

Studio is maintained by one person, so there is no guaranteed response time and no promised date for a fix. A report is read and acknowledged in the advisory. One that is confirmed is fixed and published with the next release. Please allow time for a fix to ship before you publish details. The advisory is where that is agreed.

Studio is before version 1.0. Only the newest release receives fixes.

How the product limits risk

  • Nothing listens on the network until you create an endpoint, and you choose the address and who may connect.
  • The application has no telemetry and makes no connection of its own.
  • Plugins, when they arrive, run in a separate process, and an unsigned plugin loads only after you confirm.
  • The remote control endpoint, when it arrives, is off by default and local only when first turned on.
