Virtual Serial Studio

A playground for real, virtual and networked serial ports

It opens one serial port and gives it to as many programs as you like, splits a device across virtual ports, merges publishers, bridges a port to TCP, RFC 2217 or UDP, drives the modem control lines and records the traffic.

Download for Windows, Linux or macOS Features

Free software under the GPL, version 3 or later. No account, no activation and no telemetry.

Who it is for

The Community edition is for a person working with a device. Pro and Enterprise are for a test lab that drives Studio from a test harness.

Community, free

Hobbyists and reverse engineers

Connect a device to a serial port, then watch and record the traffic while the device's own program is still using it.

  • Share one real device between the vendor's program and your own script.
  • Read the traffic as hex or text, with a timestamp on every transfer, and save it as a capture.
  • Send exact bytes, replay a capture, or script the replies.
  • Use Simple mode for a port from a short form, or Advanced mode for a diagram.

The Community edition is free and complete for this work. It has no time limit.

Test labs

Use Studio as automated test equipment: scripted rigs that drive devices and programs from the lab's own test harness and language.

What it does

Create a virtual port

Make a virtual port, or a linked pair so that two programs can talk to each other. On Windows it is a real COM port with the number you choose. On Linux and macOS it is a pseudo terminal with a stable name.

Share one device between programs

The operating system lets one program open a serial port. Studio opens it and gives each program its own port. Choose which program may write, add a listener that cannot transmit, or merge several publishers into one device.

Watch the traffic

The Monitor shows every transfer with its time, port, direction and bytes, as text or hex. Filter and search it, and export a capture that holds every byte, timed by one clock.

Bridge a port to the network

Bridge a port to TCP, RFC 2217 or UDP, as a server or a client, and bring a device from another computer onto the same diagram. You choose who may connect.

Test without hardware

A mock fixture stands in for a device. Add delay and jitter to a link, drive DTR, RTS and the other control lines, send a break, and inject faults.

Save a setup and run it from the command line

A setup is a JSON file. Open it again, start from a template, or export it as a command for vss_cli, which captures, replays and answers from a script on a machine with no display.

Privacy, source and releases

No telemetry, no analytics
Studio sends nothing about you or your ports to anyone. It opens a network connection only for an endpoint that you make.
No account and no activation server
The Community edition needs neither. A Pro licence will be a file that Studio checks offline, so a lab machine with no internet connection works.
Source you can read and build
The application, the command line tool and the driver are published under the GPL, version 3 or later. Licence.
Releases you can check
Every file has a detached signature and a SHA-512 checksum, and each release carries a software bill of materials. How to verify a download.
Known limits
A control the engine cannot back is shown disabled, with the reason. The user guide lists what the current build cannot do.
Accessibility
Every control has a name and a role, works from the keyboard, shows where the focus is, and works in light and dark themes and at 200 percent text.

Getting started

  1. Download and install. Pick the file for your system on the downloads page. The current build is {{release_tag}}, a {{release_kind}} of {{release_date}}.
  2. Choose a job. Simple mode opens with a page of jobs, such as “I need a serial port” and “Share a device”. Each is a short form with defaults.
  3. Open the port in your program. Studio shows the name to use, such as COM7 or /dev/pts/1.
