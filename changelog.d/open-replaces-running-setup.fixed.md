**Opening a setup, a template or applying the Topology JSON now replaces the setup that is running.** Before, **File > Open**, **File > Setups and templates** and **Apply changes** in the Topology JSON view added the ports and links of the new setup to the ones that were running. The window then showed the new file name with no unsaved mark, and **File > Save** wrote both sets of ports into that file. Applying the JSON of a running setup made a second copy of every port as `name-2`, or was refused when a port used a device or COM number that was already taken. The running setup now becomes the one you opened or applied, with its name, its description and its ports in the order of the file. A port that is the same in both (same name and same settings) is not touched: it keeps its COM number, a program that has it open keeps its handle, and it keeps running. A link between two such ports that is the same in both is not touched either, so data on it is not interrupted. Every other link is removed and made again, and data a port sends on it while that happens is lost, which can take up to a minute when Windows has to install a new port. A port that is not the same is removed and made again, and when it needs a COM number that Windows has not given back yet, Studio waits for it for up to 90 seconds. If the new setup cannot be made, the ports that were running are put back as far as possible (a port that comes back is a new port, and its rules, echo and the wiring and owner of its links are not restored), and the window marks the setup as changed when what runs is no longer what the file says. Opening, a new setup and quitting wait while the JSON view is applying.
