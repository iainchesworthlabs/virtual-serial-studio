**A Python client for the control endpoint.** `adapters/python` holds `vss_control`, a client for the gateway that needs Python 3.9 and no other package, so a test script can make and link ports, send bytes, wait for a pattern with `expect_bytes`, read the event and traffic streams, and keep a run and its JUnit report. It talks over the same named pipe or Unix socket as `vss_cli control`, takes a token as text or from a file, and gives each call a time limit on every system. Before it sends anything it checks that the endpoint is served by the user who runs the script, and it refuses the connection when that cannot be checked. An error of the gateway arrives as `ControlError` with the wire code, and as `EngineError` for an `engine.` code. The tests start real `vss_agent` and `vss_gate` processes; `ctest` runs them as `python_adapter` when a Python 3.9 or later is found.
