**A network client no longer drops its connection on a framing error.** A device behind a network serial server (RFC 2217) reports a framing, parity, overrun or break error when it receives a byte badly, which is common on a noisy RS485 bus. Studio treated that as the end of the connection, so the client port failed, reopened a second later and failed again, and data flowed only in short windows between reconnects. The error is now counted in the port's error total and written to the log (at most once a second, with the number left out), and the connection stays open. A test fixture port still stops on an injected fault.
