**A plugin can show you a code and ask for a remote control session.** When a running plugin has a pairing code or a one-time password for you, Studio shows it once in a dialog of its own, with the plugin's name and a countdown, and keeps it nowhere: not in the log, not on the Plugins page, not in a file. **Copy** is the only way it reaches the clipboard. When a plugin asks to use Studio's remote control, Studio asks you first: it shows who the plugin says the session is for and why, in the plugin's own words, one sentence for each thing the session could do (marking the ones that let the other side see or send data), and how long it would last. Refuse is the default, closing the dialog is Refuse, and nothing is remembered. A plugin that was granted it can also record the traffic of your ports and links into its own folder. The Plugins page also lists what Studio runs of each plugin, with **Add...** and **Remove**, and keeps that list for the next start; shows what a plugin said about its licence check; says in the approval question that a plugin which reads your licence file sees your name; and says, when a plugin changed after you decided about it, that you allowed an earlier version. A plugin that was allowed to can also replay data into a port of your setup and decode the traffic of the ports and links you name; what a decoder finds is shown on the Plugins page as a table of the newest frames and problems. When you add an instance of something that needs a port or a name, Studio asks for it first.
