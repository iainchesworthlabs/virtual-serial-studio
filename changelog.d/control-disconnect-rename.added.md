**Taking a link away and renaming a port through the control endpoint.** A program, or `vss_cli`, can now remove a link without removing its ports and give a port a new name. `vss_cli control unlink <id>` takes away the link with that id, and `vss_cli control port rename <id> <name>` renames a port; `disconnect_link(link)` and `rename_port(port, name)` do the same in the Python client. Both need the scope `control.ports`, the agent refuses both on a connection that only looks, and each use is written to the audit log with what came of it, the new name included. A name that another port has, and an empty name, are refused with the engine's error. The engine sends no event for either, so a stream only sees that the list changed.
