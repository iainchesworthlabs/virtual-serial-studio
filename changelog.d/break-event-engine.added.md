**A serial break is now carried like data.** A break is an item in the stream, in order with the bytes around it, with a start time, a length and whether the length was measured. It goes over every link and bus that carries data: through a link's delay, across a split, a join and a chain of links, into a monitor by its direction, and onto a half-duplex bus, where it holds the line for its length. A port that cannot show a break to its program says so once in the log and counts the break as dropped. The Log and the Monitor show a break as a row of its own, with its length, "at least" the length when a device did not report one, or "running" while it is held. A port's counters and a link's counters now count breaks, and so do the agent and control stats. A break set by an RFC 2217 client (SET-CONTROL 5, then 6) is carried with the length between the two commands, and the fault injection **break** on a test device is a break of one character time and no longer stops the device. The Windows driver, capture files and plugins do not carry a break yet.
