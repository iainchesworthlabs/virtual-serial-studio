**A serial break is now carried like data.** A break is an item in the stream, in order with the bytes around it, with a start time and a length. It goes over every link and bus that carries data, including delays, splits, joins, chains, monitors and half-duplex buses, where it holds the line for its length. A port that cannot show a break to its program logs that once and counts it as dropped. The Log and the Monitor show a break as a row of its own, with its length, "at least" the length when a device did not report one, or "running" while it is held. A break set by an RFC 2217 client (SET-CONTROL 5, then 6) is carried with the length between the two commands, and the fault injection **break** on a test device is a break of one character time. The Windows driver, capture files and plugins do not carry a break yet.
