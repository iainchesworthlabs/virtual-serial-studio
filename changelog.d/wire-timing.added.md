**A link can carry its traffic at the speed of a serial wire.** Turn on **Wire timing** in a link's **Settings...**, or add `"wire_timing": { "bit_rate": 115200, "framing": "8N1" }` to the link in a topology file. A write then takes as long as it would on a wire, counted from the sending port's baud rate and framing (start, data, parity and stop bits, including 1.5 stop bits), the next write waits for it to finish, and a break holds back the bytes after it for the length of the break. It is off unless you turn it on, and a file without it is saved and read exactly as before; a Studio from before it will not open a file that has it. A half-duplex bus now counts the real framing of the sender too, so 8E1 and 8N2 take 11 bits a byte and not 10. On Windows 10 (version 1803) and later the timing uses a high resolution timer, and for a gap under a millisecond Studio waits on the processor for the last part of it, using at most a tenth of one core. The link counts the releases that were late.
