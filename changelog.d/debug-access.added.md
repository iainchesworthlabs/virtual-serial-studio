**Debug access, for finding out why a port will not open.** **Settings**, **Performance**, **Debug access** lets programs on this computer ask a running Studio what its ports, its engine and Windows are doing. It is off every time Studio starts. While it is on, a status bar chip says so, and pressing the chip turns it off. A program must be allowed by you in a dialog first, and each use is written to a log in Studio's data folder. Nothing is sent anywhere. The bytes your ports carry can be read only while a second switch is on, which turns itself off after ten minutes. `vss_cli debug` is the command line client; it lists the state of every port, the calls Studio made to Windows with the code Windows gave for each failure, which COM numbers Windows keeps, the driver and the plugins. See `docs/debug-api.md`.
