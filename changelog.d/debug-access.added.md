**Debug access, for finding out why a port will not open.** **Settings**, **Performance**, **Debug access** lets programs on this computer ask a running Studio what its ports, its engine and Windows are doing. It is off every time Studio starts. While it is on, a chip in the status bar says so, and pressing the chip turns it off. A program that wants to use it must be allowed by you in a dialog first, and each use is written to a log in Studio's data folder. It uses a pipe that only you can open, nothing is sent anywhere, and the bytes your ports carry can be read only while a second switch is on, which turns itself off after ten minutes. `vss_cli debug` is the command line client. It lists the state of every port, the calls Studio made to Windows with the code Windows gave for each failure (`CreateFile`, `SetCommState` and so on), which COM numbers Windows keeps and why, the driver, the plugins and what the window shows, and it can try an operation such as adding a monitor or restarting a port with new settings and show every call that operation made. See `docs/debug-api.md`.
