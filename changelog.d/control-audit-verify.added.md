**The control gateway can check its own audit log, and on Windows it reads the access list of a directory it is given.** `vss_cli control audit verify` has the gateway check that every line of its audit log is a record, that the numbers follow each other and that each line carries the hash of the line before; it prints `intact` and the number of records, or `broken` with the file, the line and what is wrong there. It is for this user on the administration endpoint only. A broken chain shows that a line was removed, changed or moved; an intact one does not prove that nobody rewrote the whole log. On Windows, a directory for the audit log or the token file that was there before is now refused when its access list lets in anyone but this user, the system and the Administrators group; before, only its owner was looked at.
