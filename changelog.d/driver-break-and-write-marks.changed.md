**The Windows virtual COM port driver now stamps a program's break and write calls.** When a program calls `SetCommBreak` and `ClearCommBreak`, the driver records the time of each call and how many bytes the program had written before it, and the Studio helper reads the records. A break that lasts less than a poll, or begins and ends between two reads of the port state, is no longer lost, and the helper puts it in order with the bytes around it. Each `WriteFile` is stamped with the time of the call, so two writes made 10 ms apart reach the engine as two chunks with that gap, and not as one chunk with the time the helper read it. Bytes a program writes while it holds a break follow the end of the break, as a UART holds its output. The driver keeps 64 break records and 256 write records, and says how many it had to drop. This is version 5 of the driver interface: install the driver that comes with Studio, because Studio refuses a port from a driver of another version.
