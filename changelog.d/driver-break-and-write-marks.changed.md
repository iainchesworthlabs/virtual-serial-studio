**The Windows virtual COM port driver now stamps a program's break and write calls.** The driver records the time of each `SetCommBreak`, `ClearCommBreak` and `WriteFile` call, and the Studio helper reads the records. A break shorter than a poll is no longer lost, and it is put in order with the bytes around it. Two writes made 10 ms apart reach the engine as two chunks with that gap. This is version 5 of the driver interface: install the driver that comes with Studio, because Studio refuses a port from a driver of another version.
