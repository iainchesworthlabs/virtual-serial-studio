- **Saving a setup no longer risks the file you already have.** The text is written to a temporary file beside it, checked, and then put in place of the old file in one step. If the disk is full or the write fails, you get an error and your file is as it was. Before, the file was emptied first, and a failed write could leave it empty or half written while the window said it was saved.
- **A setup keeps its name, its description, the order of its ports and the target of a mock port when you open it and save it again.** Before, the name became "studio", the description was dropped, a mock port's target went back to the default, and the ports could be written in a different order each time.
- **A port made on a com0com pair no longer stops every save.** File > Save, the Topology JSON view, the setup kept for the next start and the diagnostic bundle all failed for as long as such a port existed.
- **A setup file with a mistake is refused instead of read as something else.** A member of the wrong type (such as `"kind": ["tcp"]` or `"capture": "false"`), a member Studio does not know (such as `"port"` for `"ports"` or `"delay"` for `"delay_ms"`), a missing `"version"` or a `"version"` other than 1 now gives an error that names the member. Before, the mistake was read as a default and saving then wrote the loss back over the file.
- **A file over 16 MiB is refused when you open it** instead of being read into memory, which could freeze the window or stop Studio and every running port.
