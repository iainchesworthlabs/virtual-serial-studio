**Windows has an installer that sets up the virtual COM port driver.** The release now holds `virtual-serial-studio-<tag>-windows-x86_64.exe` beside the zip. It installs Studio and the command line tool for all users in `Program Files\Virtual Serial Studio`, adds a Start menu entry and an uninstaller to Apps & features, replaces an earlier version when you upgrade, and can put `vss_cli` on the PATH (off unless you tick it). A page with a ticked box also installs the user-mode virtual COM port driver and its helper service (`/S /DRIVER=0` skips them in a silent install); the uninstaller removes both. The installer adds no certificate and does not turn on test signing: when Windows does not trust the signature on the driver files, Studio is installed anyway, the driver is not, and the installer says why and what to do (`bin\driver\trust\install-trust.ps1`, then **Set up Virtual Serial Studio**), with a log in the install folder. The installer and every program and driver file in it are signed the way the release signs them (`SIGN_WINDOWS`), and the release workflow installs it, runs both programs from the installed folder and uninstalls it before the file is published. The zip now carries the driver files in `bin\driver`, so **Set up Virtual Serial Studio** works from it too. The kernel-mode driver is not included; `docs/releasing.md` says why and what is left.
