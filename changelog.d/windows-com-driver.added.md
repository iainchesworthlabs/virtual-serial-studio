**Virtual COM ports on Windows from Studio's own driver.** The `vsscom` driver makes COM ports on demand, so a program that wants a serial port gets one without com0com. It follows the rules of a real port: reads wait under the `SetCommTimeouts` combinations, `WaitCommEvent` and `SetCommMask` behave as documented, DTR and RTS control and handshake modes drive the lines. A port goes away when the process that asked for it ends, and it keeps its COM name from run to run. Up to 32 ports exist at once and one user holds at most 16. There is a kernel-mode driver and a user-mode one (`vsscom_um`, which needs no kernel-mode signature), and a helper service, `vsscom_helper`, so Studio needs no administrator rights to open a port. **The driver package is not production-signed yet**: Windows loads it only with test signing on, or after `drivers/windows/trust/install-trust.ps1` has made the machine trust the release certificate. See `docs/windows-com-driver.md`.
