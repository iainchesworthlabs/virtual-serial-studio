**Virtual COM ports on Windows from Studio's own driver.** The `vsscom` driver makes COM ports on demand, so a program that wants a serial port gets one without com0com. It follows the rules of a real port: reads wait under the `SetCommTimeouts` combinations, `WaitCommEvent` and `SetCommMask` behave as documented, `SetCommState` DTR and RTS control and handshake modes drive the lines (old programs rely on this), `PurgeComm` and `CancelIoEx` never hang, and a killed or suspended program frees its port. A port goes away when the process that asked for it ends, so a crashed Studio leaves nothing behind, and it keeps its slot and COM name from run to run. Up to 32 ports exist at once and one user holds at most 16. There is a kernel-mode driver and a user-mode one (`vsscom_um`, which needs no kernel-mode signature), and a helper service, `vsscom_helper`, makes ports for ordinary users so Studio never needs administrator rights to open one. The driver has been run under Driver Verifier and tested with 32-bit programs under WOW64. **The driver package is not production-signed yet**: Windows loads it only with test signing on, or after `drivers/windows/trust/install-trust.ps1` has made the machine trust the release certificate. See `docs/windows-com-driver.md`.
