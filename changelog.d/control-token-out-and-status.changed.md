**`vss_cli control token create --out` makes a private file first, and `status` says only what it knows.** `--out=<file>` now needs a name that is not a file yet: the file is made first, empty, and only you can read it from that moment (on Windows its access list names only you); it never replaces a file or follows a link. When the file cannot be made, `token create` makes no token and shows nothing, and when the token cannot be written to it, the token is revoked and the file is removed, so a second run with the same name fails instead of leaving a token that nobody holds. A token that names a transport twice is refused when it is made, and a token file that `vss_gate` cannot read stops it with a message that names the file and the token. `vss_cli control status` says `Remote control: on` and whether it reached the gateway over the local pipe or socket or over TCP; it does not say which other ways in are open, because the gateway does not tell it yet. `vss_gate --loopback-port` can be started again on the same port as soon as the one before it has stopped. `vss_cli control run begin` and `run record`, and the Python client, cut a name of more than 128 bytes and a message of more than 512 to that length and end it in `...`, so a failed check is still recorded.
