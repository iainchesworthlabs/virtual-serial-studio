**Waiting for bytes through the control endpoint.** A test can now ask the gateway to wait for bytes on a port and, in the same request, to send bytes to a port once it is listening (`expect.bytes`, `vss_cli control expect <id> --pattern=<digits>`), so a reply cannot be missed between sending and starting to listen. The answer says how many bytes went by before the pattern and when the pattern was completed, as in `matched 6 1234567890 0`, with the number of events lost while it listened. A pattern that does not come ends as a timeout and the connection stays open. Waiting needs the scope `monitor.data`, and sending with it needs `control.data` as well. The audit log has one record for each wait with how it ended; it holds neither the pattern nor the bytes sent.
