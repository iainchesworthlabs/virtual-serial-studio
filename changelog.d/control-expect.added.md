**Waiting for bytes through the control endpoint.** A test can ask the gateway to wait for bytes on a port and, in the same request, to send bytes to a port once it is listening (`expect.bytes`, `vss_cli control expect <id> --pattern=<digits>`), so a reply cannot be missed. The answer says how many bytes went by before the pattern, as in `matched 6 1234567890 0`, and how many events were lost. A pattern that does not come ends as a timeout and the connection stays open. Waiting needs the scope `monitor.data`, and sending with it needs `control.data` as well.
