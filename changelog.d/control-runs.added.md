**Test runs and a JUnit report through the control endpoint.** A harness can now open a named run (`runs.begin`, `vss_cli control run begin <name>`). While it is open the gateway notes how each `expect.bytes` of the same user or token ended, on any of its connections, and under the name given with `label` (`--label=<text>` on `vss_cli control expect`); the harness adds checks of its own with `runs.record` (`run record <name> --outcome=passed|failed|error|skipped`). `runs.end` closes the run and gives its counts (`run end`), and `report.junit` gives the run as a JUnit XML document (`run report [<id>] [--out=<file>]`) that a test runner or a CI system can read. A run belongs to whoever opened it, across connections, so separate `vss_cli` commands of the same user fill one run, and it can be read only by that user or token and by the administration endpoint. The names and messages in a report come from clients and are written so that they cannot change the report's structure. A run keeps 1000 checks and the gateway keeps the last eight runs. The four run operations need the scope `monitor`.
