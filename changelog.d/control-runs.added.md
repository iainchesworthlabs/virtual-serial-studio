**Test runs and a JUnit report through the control endpoint.** A harness can now open a named run (`vss_cli control run begin <name>`). While it is open the gateway notes how each `expect.bytes` of the same user or token ended, under the name given with `label` (`--label=<text>` on `vss_cli control expect`); the harness adds checks of its own with `runs.record` (`run record <name> --outcome=passed|failed|error|skipped`). `runs.end` closes the run and gives its counts (`run end`), and `report.junit` gives the run as a JUnit XML document (`run report [<id>] [--out=<file>]`). A run can be read only by the user or token that opened it and by the administration endpoint. A run keeps 1000 checks, and the gateway keeps eight runs. The run operations need the scope `monitor`.
