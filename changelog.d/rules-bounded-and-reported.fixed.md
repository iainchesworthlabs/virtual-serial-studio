**A response rule set that fires too fast is stopped after a bounded amount of work, and Studio says so.** One large write could make a rule set build every reply before its limits were applied; the limits are now applied first. A reply may have at most four check values. A set that is suspended, installed, removed or late writes a line to the Log. `"precision": "tight"` is refused, because this build has no timing thread. Rule sets cannot be installed on a port yet, so no running setup was affected.
