**Every build says which commit it was made from, and so does every plugin.** The version in About, in `vss_cli --version` and in the diagnostic information now reads like `v0.1.0-rc.5+18.g7d42b4e.build.6083`: the release, the number of commits after its tag, `g` and the short commit, the CI run number, and `.dirty` when the tree was modified. A plugin's `version` may now carry the same build metadata after a plus sign, such as `0.1.0+57.g7ffbece`. The Plugins list, the detail, Copy details and `vss_cli plugin list` show all of it, so a newer build of the same version can be told from an older one. The metadata is kept and shown and takes no part in the order, as Semantic Versioning says, so a plugin that carries it is checked, compared and revoked as before, and a plugin may still say the plain version in its `hello`.
