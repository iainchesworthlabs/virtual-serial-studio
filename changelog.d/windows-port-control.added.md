**On Windows, Studio can see what a program is doing with a port and take it back from a program that has hung.** The Ports list shows **Waiting for program** and **Program connected** for a Studio driver port, the baud rate and framing the program set, and the program's process; each open and close is written to the port's log with the time and process. **Release port...** in the Inspector names the program, says how long no data has passed (a fact; it does not claim the program is stuck) and offers two confirmed ways out: take the port back (the program keeps running, its connection to the port fails, and another program can open the port at once with the same COM number) or end the program (your own programs only, unless Studio runs as administrator). If the helper service or the driver restarts and removes the ports under your programs, a **Some COM ports were lost** banner offers **Recreate ports**, which makes them again with the COM numbers they asked for. Driver and Studio share a versioned interface (version 3), so update them together.
