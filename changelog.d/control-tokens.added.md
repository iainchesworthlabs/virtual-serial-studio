**Tokens for the control endpoint.** `vss_cli control token create --label=<name> --role=monitor|control|control-apply` makes a token on the computer that runs `vss_gate`, shows it once, and keeps only its SHA-256 in a file only you can read. A program that presents the token connects as that token, with the token's scopes and not yours; `vss_cli control status --token-file=<file>` shows what a token may do. Tokens end after 30 days unless `--days` says otherwise (a year at most), `vss_cli control token list` shows them, and `vss_cli control token revoke <id>` ends one at once and closes its sessions. Making, listing and revoking tokens is possible only through the administration endpoint, never with a token. A wrong, unknown, revoked or expired token always gets the same refusal, repeated wrong tokens are slowed down, and the audit log records each refusal with its reason and never the token.
