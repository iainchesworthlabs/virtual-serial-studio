**Tokens for the control endpoint.** `vss_cli control token create --label=<name> --role=monitor|control|control-apply` makes a token on the computer that runs `vss_gate`, shows it once, and keeps only its SHA-256 in a file only you can read. A program that presents the token connects as that token, with the token's scopes and not yours; `vss_cli control status --token-file=<file>` shows what a token may do. Tokens end after 30 days unless `--days` says otherwise (a year at most), `vss_cli control token list` shows them, and `vss_cli control token revoke <id>` ends one at once and closes its sessions. Making, listing and revoking tokens is possible only through the administration endpoint, never with a token. A wrong, unknown, revoked or expired token always gets the same refusal, repeated wrong tokens are slowed down, and the audit log records each refusal with its reason and never the token. `vss_cli control token create --out=<file>` makes a new file that only you can read from the moment it exists (on Windows its access list names only you), and never uses a file that is already there or follows a link; if the file cannot be made private it writes nothing and shows the token on the screen. A token that names a transport twice is refused when it is made, and a token file that `vss_gate` cannot read now stops it with a message that names the file and the token.
