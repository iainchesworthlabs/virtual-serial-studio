**Setup check now looks at RFC 2217 listeners and listeners with an allow list.** The Windows Firewall check only read plain `tcp-listen://` and `udp-listen://` addresses. A port on `rfc2217-listen://`, or on an address ending in `?allow=`, was left out, so Setup check showed the firewall as fine and never offered **Allow in Windows Firewall**, while other computers could not connect. `vss_cli permissions check --listen=` accepts them too.
