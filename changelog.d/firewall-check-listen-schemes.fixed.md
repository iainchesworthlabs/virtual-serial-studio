**Setup check now looks at RFC 2217 listeners and listeners with an allow list.** The Windows Firewall check only read `tcp-listen://` and `udp-listen://` addresses with no extra text. A port listening on `rfc2217-listen://`, or on any address ending in `?allow=`, was left out, so Setup check showed the firewall as fine and never offered **Allow in Windows Firewall**, while other computers could not connect. `vss_cli permissions check --listen=` also refused these addresses. The check now reads an address with the same code the listening port uses.

**The firewall helper refuses a rule for every network.** `vss_cli permissions firewall-allow` accepted `--profiles=domain,private,public`, which opens the port on domain, private and public networks, although the documentation says it never does. It now refuses that, and Setup check offers the private network when the computer is on all three at once. A rule for one or two networks still works.
