**A write that is thrown away now reports an error, and a reopen no longer leaves a port with two reads.** A write that was waiting when its port was reopened, closed or removed, or when an earlier write failed, was dropped without any answer, so the benchmark and `vss_cli bench` stopped with an exception instead of an error. Every waiting write now ends with an error. Changing a port's settings while data was arriving could leave the port with two reads at once, which could lose or repeat bytes for as long as the port stayed open. A write made at the same moment as a reopen could be sent twice. Reading the state of a port while it is reopened could also read a half-changed port. A read of the old connection that failed just as a port was reopened could close the new connection. All of these are fixed.
