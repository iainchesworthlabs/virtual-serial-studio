**Control over TCP on this computer.** `vss_gate --loopback-port=<port>` now also serves the control API on TCP at `127.0.0.1` and `::1`. It is off unless the option is given, and it cannot listen on any other address. Who connects over TCP is not known, so every TCP connection needs a token made for it (`vss_cli control token create --transport=loopback`); a token made for one transport is refused on the other, and a token made without `--transport` is for the local pipe or socket alone. A connection that does not begin with the API's preface is closed without a reply. `vss_cli control ... --loopback-port=<port> --token-file=<file>` and the Python client's `loopback_port` use it. `vss_cli control token list` now shows where each token is good, and a connection that is refused ends with the code name, as in `not authenticated (unauthenticated)`.
