**Control over TCP on this computer.** `vss_gate --loopback-port=<port>` now also serves the control API on TCP at `127.0.0.1` and `::1`. It is off unless the option is given, and it cannot listen on any other address. Every TCP connection needs a token made for it (`vss_cli control token create --transport=loopback`); a token made for one transport is refused on the other, and a token made without `--transport` is for the local pipe or socket alone. `vss_cli control ... --loopback-port=<port> --token-file=<file>` and the Python client's `loopback_port` use it.
