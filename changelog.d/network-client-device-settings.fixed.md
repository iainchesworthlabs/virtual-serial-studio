**A network client no longer changes the serial settings of the device it connects to.** Connecting to a network serial server (RFC 2217), Studio used to set its own baud rate, data bits, parity, stop bits and flow control on the server's real port, 115200 8N1 unless you had chosen others. On a bus that runs at another rate, such as a 9600 baud pool controller behind a network serial server, that made every byte a framing error. The client now asks the server for its settings and uses what it answers, and the port's settings show what the device has. A speed or framing a program sets on the other side of the link is still sent to the server. An address that says `settings=own`, or that carries its own `baud`, `data`, `parity`, `stop` or `flow`, sets them from Studio. The client also takes part in the Telnet binary and suppress-go-ahead options that serial servers expect, which it used to refuse.
