**`vss_cli` stays alive when it says it does, refuses what it does not understand and reports what it sent.** `run`, `share`, `join`, `bridge` and `loopback` now keep their ports until Ctrl-C, SIGTERM or, on Linux and macOS, SIGHUP (a closing terminal), or on Windows until Ctrl-Break or the console window closes, or until `--seconds=N` is over, as `bus`, `virtual` and `capture` already did; they used to print what they made and exit at once without `--seconds`. A second Ctrl-C or Ctrl-Break on Windows no longer ends a command before its ports are down, and a closing terminal also takes the `vport` links away. `--seconds` must be 1 or more; `--seconds=0` is refused. Every option can be written `--name=value` or `--name value`. An option a command does not have, a missing value, a value that is not a whole number where one is needed and a stray word are one line on standard error and exit code 2, not something ignored. `--help` and `-h` print the help on standard output and exit with 0, and `vss_cli --version` prints the version of the build as `vss_gui --version` does, for example `vss_cli v0.1.0-rc.3+build.6083-3de4617`. `vss_cli virtual --com=N` fails, instead of making a port with another name, when the Windows driver is not there. `vss_cli play` waits until the port has written what it queued, whatever else is written to the same port meanwhile, and prints what was written; it exits with 1 when the port refused a write or stopped taking bytes. `vss_cli devices --json` is now one line, escapes the names it prints, replaces bytes that are not UTF-8 so that the output is valid JSON, and adds each port's `hardware_id`.
