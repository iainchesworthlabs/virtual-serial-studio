**`vss_cli` stays alive when it says it does, refuses what it does not understand and reports what it sent.** `run`, `share`, `join`, `bridge` and `loopback` now keep their ports until Ctrl-C, SIGTERM or, on Linux and macOS, SIGHUP (a closing terminal), or until `--seconds=N` is over, as `bus`, `virtual` and `capture` already did; they used to print what they made and exit at once without `--seconds`. A closing terminal also takes the `vport` links away. Every option can be written `--name=value` or `--name value`. An option a command does not have, a value that is not a whole number where one is needed, a missing value and a stray word are one line on standard error and exit code 2, not something ignored. `--help` and `-h` print the help on standard output and exit with 0, and `vss_cli --version` prints the version as `vss_agent --version` does. `vss_cli virtual --com=N` fails, instead of making a port with another name, when the Windows driver is not there. `vss_cli play` waits until the port has written what it queued, and says so and exits with 1 when the port took only part of it. `vss_cli devices --json` escapes the names it prints, so the output is always valid JSON, and adds each port's `hardware_id`.
