**Making ports and sending bytes through the control endpoint.** A program, or `vss_cli`, can now make and remove ports, link two ports and send bytes to a port through the control endpoint. `vss_cli control port create <name>` and `vss_cli control link <id> <id>` print the id of what they made, `vss_cli control port remove <id>` removes a port, and `vss_cli control send <id> --hex=<digits>` sends the bytes, 64 KiB at most. Making, removing and linking ports needs the scope `control.ports`, and sending needs `control.data`. The default role of the local user, `monitor`, has neither, so the gateway has to be started with `--local-role=control` or a program has to use a token with those scopes. Every such request is written to the audit log with what came of it; the bytes of a send are not, only how many.
