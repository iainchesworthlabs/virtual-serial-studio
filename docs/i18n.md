# Languages

The application is written in English and has nine languages: English,
French (`fr`), Spanish (`es`), German (`de`), Hebrew (`he`), Yiddish (`yi`),
Japanese (`ja`), Simplified Chinese (`zh_CN`) and Arabic (`ar`). Hebrew,
Yiddish and Arabic are written right to left. The window has no language
setting: it follows the system, or `VSS_LANGUAGE`.

## How the language is chosen

`vss::gui::apply_language()` runs once at start-up. It takes the system's
preferred languages in order, matches each by its language alone and uses the
first one that has a catalogue in the program: any `en-*` is English, `de-*` is
German, `iw` and `ji` are the old codes of Hebrew and Yiddish, and `zh` is
Simplified unless the tag says Traditional (a Hant script, or Taiwan, Hong Kong
or Macao), which has no catalogue and is passed over. Nothing that matches
gives English. The program does not leave this to the platform's translator
search, because what the platform lists differs from system to system.

A right-to-left language also sets the layout direction of the whole
application. A language without a catalogue is never chosen, so English text is
never mirrored.

The Language row of About and of the support bundle's environment text shows
the language chosen and the languages the system offered, so a report of the
wrong language can be answered from a screenshot. To try a language, set
`VSS_LANGUAGE` to its code before starting the program, for example
`VSS_LANGUAGE=he vss_gui`.

## Catalogues

Each language but English has a catalogue, `apps/vss_gui/translations/vss_gui_<code>.ts`.
The build turns it into a `.qm` file inside the program (`:/i18n/vss_gui_<code>.qm`).
Strings are English source text in `tr()`, and a string with a number or a name
in it uses `%1` placeholders, never concatenation.

```bash
cmake --build --preset linux-debug-gui --target update_translations
```

refreshes the `.ts` files from the sources. The `release_translations` target
builds the `.qm` files. A language is complete when every source string has a
translation that is not marked unfinished and keeps the placeholders of the
source.

## Working on a catalogue

`tools/ts_tool.py` works on a catalogue as JSON, so a translator can be a person
with a text editor or a program:

```bash
python3 tools/ts_tool.py export apps/vss_gui/translations/vss_gui_de.ts todo.json
python3 tools/ts_tool.py apply  apps/vss_gui/translations/vss_gui_de.ts done.json --origin "..."
python3 tools/ts_tool.py fill   apps/vss_gui/translations/vss_gui_de.ts
python3 tools/ts_tool.py check  apps/vss_gui/translations/vss_gui_de.ts
```

`export` lists each unfinished source text once, however many dialogs use it.
`apply` writes an answer to all of them, refuses an answer whose placeholders
differ from the source, marks them finished, and keeps the origin note in the
file header. `fill` copies a finished translation to every unfinished message
with the same source text, which is what `update_translations` leaves when a
text moves to another context. `check` fails when any message is unfinished or
empty or has different placeholders from its source. After `update_translations`
adds new strings to the catalogues, `fill`, then export, translate the new ones
and apply them the same way.

## Adding a language

1. Add the code to `supported_languages()` in
   `apps/vss_gui/src/language/language_choice.cpp`, and to the list the test
   `language: every language of the standard is supported` expects in
   `test_language_choice.cpp`. For a right-to-left language add it to
   `is_right_to_left()` as well. If the system's tags do not name the
   catalogue the way the code does (as `zh` and `zh_CN`), `catalogue_for()` in
   the same file maps them.
2. Create `apps/vss_gui/translations/vss_gui_<code>.ts` as an empty catalogue
   (`<TS version="2.1" language="<code>"></TS>`). The build finds catalogues by
   the pattern `vss_gui_*.ts` when CMake runs, so configure again.
3. Run `update_translations` to fill it with the source strings, then translate
   it with `tools/ts_tool.py` as above.

`vss_gui_language_tests` then holds the new catalogue to the same rules as the
others.

## Origin and review of each language

Every catalogue is a machine translation that no speaker of the language has
reviewed. The header of each `.ts` file records where it came from ("Written by
Claude for the flow usability pass"), and the unit test `vss_gui_language_tests`
fails if a catalogue is missing a string, has an unfinished or empty
translation, or changes a placeholder.

| Language | Origin | Reviewed by a speaker |
|---|---|---|
| French (`fr`) | Machine translation | No |
| Spanish (`es`) | Machine translation | No |
| German (`de`) | Machine translation | No |
| Hebrew (`he`) | Machine translation | No |
| Yiddish (`yi`) | Machine translation | No |
| Japanese (`ja`) | Machine translation | No |
| Simplified Chinese (`zh_CN`) | Machine translation | No |
| Arabic (`ar`) | Machine translation | No |

Yiddish has few established computing terms, so the translation uses
English-derived words in Hebrew script where none exists; a speaker should
review it first.

## Known gaps

- Strings must reach `lupdate` through `tr()`, `QObject::tr()`,
  `QCoreApplication::translate("Context", "text")` or `QT_TRANSLATE_NOOP` in a
  table. A helper that takes the text as a variable hides it from `lupdate`:
  the text is then translated at run time but is in no catalogue, and stays
  English.
- The share wizard names the port that stays inside Studio with an ordinal word
  ("third"). Each word is its own entry in the `ordinal` context so a language
  can inflect it to fit the sentence: French, Spanish, Hebrew and Arabic use
  words, Japanese and Chinese use a number with the ordinal marker, and German
  and Yiddish use a numeral because the word would change with the case.
- Texts that carry a count use `%n` where the source has a plural form, and a
  plain `(s)` form in the setup check, which Qt does not pluralise.
- The catalogues were checked for completeness, not for fit: some German and
  Arabic labels clip in the compact window.
