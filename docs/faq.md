<h2 class="icl-sr">The questions</h2>
<div class="icl-faq">
<details><summary>What does it replace?</summary><p>On Windows it makes <code>COM</code> ports with its own driver, so you do not need com0com. On Linux and macOS, <code>vss_cli vport</code> makes pseudo terminals with stable names and can join two of them like a null-modem cable. It also gives one real device to several programs, which a plain serial port cannot do. <a href="../products/drivers/">Drivers and virtual ports</a>.</p></details>
<details><summary>Which ports can it share?</summary><p>Studio opens a real serial device once and gives each program its own virtual port. A network port, <code>tcp</code>, <code>udp</code> or <code>rfc2217</code>, is a port like any other, so it can be shared the same way. You can have up to 32 virtual ports at once. A device that another program already holds cannot be attached, and Studio tells you when attaching fails. <a href="../solutions/sharing-and-bridging-ports/">Sharing and bridging ports</a>.</p></details>
<details><summary>Will it work with my existing program?</summary><p>A program that opens a <code>COM</code> port, or a device path such as <code>/dev/pts/3</code>, can open a virtual port. Some programs need care. On Windows a program that builds the name as <code>"COM%d"</code> needs a number from 1 to 9, and Studio lets you choose the number. On Linux and macOS a program that lists the ports it detects does not list a pseudo terminal, so give it the path. <a href="../guide/windows/#old-programs-on-windows">Old programs on Windows</a>.</p></details>
<details><summary>Why does a virtual port on Windows need a driver?</summary><p>On Windows a <code>COM</code> port is a kernel device and not a name, and nothing that runs as an ordinary program can make one. Studio ships a driver that makes them. Linux and macOS have pseudo terminals built in, so they need no driver. <a href="../products/drivers/">Drivers and virtual ports</a>.</p></details>
<details><summary>Why is the driver test-signed?</summary><p>It is signed with a certificate from the certificate authority of Iain Chesworth Labs. Windows accepts it only on a computer where that authority has been installed. On any other computer the installer installs Studio, leaves the driver out and says why. A driver signed by Microsoft would install with no step by hand. It does not exist yet. <span class="vss-chip vss-chip--plan">Planned</span> <a href="../platforms/windows/">Windows</a>.</p></details>
<details><summary>Can it run with no window?</summary><p>Yes. <code>vss_cli</code> has no window and no Qt. It reads the same JSON setup file as Studio, and <code>vss_cli run</code> keeps the ports until you press Ctrl-C, send SIGTERM, or ask for a number of seconds. So a setup built in the window can run in a CI job. <a href="../products/command-line/">Command line</a>.</p></details>
<details><summary>How do I script it?</summary><p>From a shell, use <code>vss_cli</code>. From a test, start <code>vss_agent</code> and <code>vss_gate</code> and use the Python client <code>vss_control</code>: it makes and links ports, sends bytes, waits for a reply and hands back a JUnit report. The agent, the gateway and the client are built from source today and are not in a package. <span class="vss-chip vss-chip--src">Built from source only</span> <a href="../products/agent-gateway/">Agent and gateway</a>.</p></details>
<details><summary>Can it record what goes over a port?</summary><p>Yes. The Monitor shows every byte with its time and direction, as text or hex. A capture can be exported, and <code>vss_cli capture</code> records from a terminal as <code>.cap</code>, CSV or JSON Lines. <code>vss_cli play</code> writes a recording back at the times it was made. <a href="../solutions/capture-and-analysis/">Capture and analysis</a>.</p></details>
<details><summary>Can it pretend to be a device?</summary><p>Yes. A mock fixture can echo, or send text, a pattern, a counter or random bytes at a set rate. <code>vss_cli respond</code> makes a port answer requests from a JSON script, with a delay you choose, or poll like a master. <a href="../solutions/device-emulation/">Device emulation</a>.</p></details>
<details><summary>Can I put a serial port on the network?</summary><p>Yes, as <code>tcp</code>, <code>udp</code> or <code>rfc2217</code>, either as a client that connects out or as a listener that waits. None of them is encrypted and RFC 2217 has no password, so listen on <code>127.0.0.1</code> and use an SSH tunnel or a VPN, or list the computers that may connect. <a href="../security/#bridges">Ports you put on a network</a>.</p></details>
<details><summary>Does it send anything anywhere?</summary><p>No telemetry, usage data, crash reports or account. The one request Studio makes by itself is the optional update check, which is off until you turn it on and sends nothing about you or your computer. A licence is checked on the computer and never sent. <a href="../privacy/">Privacy</a> and <a href="../security/#network">what the program sends over a network</a>.</p></details>
<details><summary>What does the Community edition lack?</summary><p>Nothing that is built. It is the whole application, free under the GPL. Pro and Enterprise add a licence file, support and terms agreed with you. What is planned for them is not built yet. <a href="../pricing/">Pricing</a>.</p></details>
<details><summary>What is planned and not built?</summary><p>Official plugins, a Windows driver signed by Microsoft, controlling one computer from another with TLS, client libraries for languages other than Python, response timing and fault injection that a test or <code>vss_cli</code> can reach, licence gating of features, update checks (the client exists, and no key is built in), and packages that hold the agent and gateway. <a href="../products/">Products</a> marks each one Planned.</p></details>
<details><summary>Can I use it at work, for free?</summary><p>Yes. Studio is under the GNU General Public License, version 3 or later, which allows use at work. If you distribute a program that includes Studio's code, the licence's terms apply to that program too. Take your own advice for your case. <a href="../licensing/">Licensing</a>.</p></details>
<details><summary>Which systems does it run on?</summary><p>Windows on x86-64, macOS on Apple silicon, and Linux on x86-64. The macOS files are not signed or notarised, so macOS asks you to confirm. The Linux files need glibc 2.42 or newer. <a href="../platforms/">Platforms</a>, with the exact limits of each.</p></details>
<details><summary>How do I report a problem?</summary><p>Open an issue on GitHub with the version, the system, what happened and what you expected, and the smallest setup file or command that shows it. Studio can save a support bundle, which never holds your traffic. Do not attach captures taken from equipment that is not yours. A security problem goes through GitHub's private form. <a href="../support/">Support</a>.</p></details>
</div>
