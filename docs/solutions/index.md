<h2 class="icl-sr">The four solutions</h2>
<ul class="icl-grid vss-grid-3">
<li><article class="icl-card"><h3><a href="develop-and-test-without-hardware/">Develop and test without hardware</a></h3><p>Give your program a serial port before the device exists. Make the other end answer like the device, and slow the line down or break it.</p></article></li>
<li><article class="icl-card"><h3><a href="sharing-and-bridging-ports/">Share a device and put it on the network</a></h3><p>Let several programs use one device, take turns sending to it, or use it from another computer.</p></article></li>
<li><article class="icl-card"><h3><a href="capture-and-analysis/">Watch and record traffic</a></h3><p>See every byte on a port with its time, keep it in a file, and play it back.</p></article></li>
<li><article class="icl-card"><h3><a href="test-automation-and-ci/">Automate tests in a lab</a></h3><p>Save a setup as a file, run it from a terminal or a CI job with no window, and keep a test report.</p></article></li>
</ul>
</div></section>

<h2>Before you start</h2>
<ul class="vss-ticks">
<li>Windows needs the Studio driver for virtual <code>COM</code> ports. It is test-signed, so Windows accepts it only where the certificate authority of Iain Chesworth Labs is trusted.</li>
<li>The agent, the gateway and the Python client are built from source and are not in the packages.</li>
<li>Network ports do not encrypt anything.</li>
</ul>
