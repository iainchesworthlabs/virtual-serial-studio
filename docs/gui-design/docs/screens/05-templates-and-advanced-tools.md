Mockups: Templates, Advanced, Faults, AddFixture, JsonView, Benchmark, Palette.

## Setups and templates (Templates.html), width 920
Opens: File, Setups and templates, and the launcher's Saved setups row. Title "Setups". Sub "Start from a ready-made setup, or open one you saved." Search field "Search setups". Tabs "Templates" and "Recent".
- Template PickCards (2 by 2): **Test bench, no hardware** "Two Studio-only ports and a one-way link, so a fresh PC can show the whole data path." (Basic, 2 ports 1 link; this is the old null-modem demo). **Share a device with three programs** "One real device split to three ports, each ready for its own program." (Intermediate, 4 ports 1 link). **Device on the network** "A serial device bridged to a TCP port, both directions visible in the monitor." (Intermediate, 2 ports 1 link). **Two programs, one device, one at a time** "Two programs joined into one device, with an owner so writes never collide." (Advanced, 3 ports 1 link).
- Recent table: file name in mono, summary, "Last opened <date>", button Open.
- Footer: "Browse for a file", "Save current setup as template", Cancel, primary "Use template".
- Templates are JSON topology documents bundled as Qt resources and validated by the same code as File, Open. Using a template opens a new setup with unsaved changes marked `*`. Real-device templates ask for the device through the Attach dialog.

## Owner control (Advanced.html link bar), story B3
When a port that is the target of a join with the owner policy is selected, the Topology dock shows a link bar under the diagram: "Links on device", chip "Join", text "recipe-tool and qa-runner into device". Row "If both write at once" with a combo (One owner at a time, Mix bytes as they arrive). Row "Owner now" with chip "qa-runner", and buttons "Release owner" and "Give to recipe-tool". The owner's node shows an "Owner" chip, a node whose bytes are being dropped shows a "Dropped" chip, the ports table shows Dropped bytes, the monitor shows DROP rows, and the status bar shows "214 B dropped, not owner". These use the engine's owner arbitration (`set_owner`, `release_owner`). A split with the owner policy and two or more targets (the Simple-mode "Let programs take turns sending to a device" setup) shows the same bar. Its chip reads "Split", its text reads "device to recipe-tool and qa-runner" and "Give to" offers a target; the device the targets share is never offered, because the owner of a duplex link is one of its targets. When no link has an owner to control, Topology, Owner says "Select the target of a join or the device of a split with the owner policy to control who writes."

## Line wiring and fault injection (Faults.html), width 1100
Opens: Inspector, "Open line matrix and faults". Title "Inspector: modem" with chips "Fixture (mock)" and the state, and an ADVANCED badge. Sub "Linked two-way to **terminal**. Wiring changes apply to that link only."
- Left, "Line wiring": SegmentedControl "Standard null-modem", "Loopback", "Custom". Switch "Emulate modem lines". Matrix with real checkboxes (rows DTR and RTS, columns DSR, CTS, DCD, RI), caption "Column headings are the inputs on terminal. The same wiring applies in the other direction." Standard preset: DTR to DSR, RTS to CTS, DTR to DCD. Info: "With this wiring, raising DTR on modem raises DSR and DCD on terminal. Raising RTS raises CTS." Card "Line state now": switches "DTR on", "RTS off", button Break, four input chips.
- Right, "Inject a fault": six tiles each with an Inject button: Parity error "Byte arrives with bad parity", Framing error "Byte arrives with no valid stop bit", Overrun "Incoming data lost, too fast", Break "A break is received on the line", Hang-up "Carrier drops, as a modem does", Disconnect "Device vanishes, as if unplugged". Table "Injected so far": Time, Fault, Result ("Error event reported on modem"). CodeBlock "Create this fixture in code": `studio app;` and `const auto device = app.create_mock_port("modem");`.
- Footer: muted "Faults are only available on fixture ports." and primary Close.
- Engine: the mock backend can inject these faults. Per-link wiring is not in the engine today (fixed null-modem crossing with an on or off switch). See 08-engine-gaps.md. Note the project docs disagree on DCD: confirm with the maintainer and keep the preset in one data table.

## Add a mock fixture (AddFixture.html), width 760
Title "Add a mock fixture" with ADVANCED badge. Sub "A pretend device you can script, for testing without hardware." Fields: Name (default `modem`), Baud rate (default 115200), "Connect it to" combo (default the selected port, two-way, or "Nothing yet"). Hint "You can link it later from Connect ports." ## Benchmark (Benchmark.html), width 760
Opens: Tools, Benchmark. Title "Benchmark a connection" with ADVANCED badge. Sub "Sends data from one port to another and counts what arrives." Combos "Send from" and "Receive on", "Amount of data" (1 MB, 10 MB, 100 MB), "Chunk size" (1 KB, 4 KB, 64 KB). Info: "Do not link these two ports in Studio. The data has to travel through the cable or driver pair, so the count means something." Result card: chip "Passed, every byte arrived" (or "Failed, N bytes short"), progress bar, four metrics (Sent, Received, Lost, Throughput). Text: "A run fails when the received count is short, and the result says by how much." CodeBlock `vss_cli bench --from=serial://COM3 --to=serial://COM5 --bytes=10MB --chunk=4KB`. Footer: "Copy result", Close, primary "Run again". While running: progress with Cancel. The two ports must not be linked in the studio: block the run with the reason if they are. The mockup numbers are samples only.

## Command palette (Palette.html), width 760
Opens: Ctrl+K and the toolbar search field. A frameless dialog centred over the window with a large search field (18px) and an Esc key cap. Results grouped "Available now" and "Needs Advanced mode". Matches action text and keywords. Empty group message: "Nothing in Simple mode matches "fault"." A selected hidden action shows its row highlighted; Enter turns on Advanced mode (footer text "Advanced mode adds panels and options to this window. Nothing you have built changes.", primary "Turn on Advanced mode") and then runs the action. Arrow keys move, Enter runs, Escape closes. Built from one `ActionRegistry` that every menu and toolbar action registers into, with text, keywords, shortcut and required level.
